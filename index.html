What happens when “one-time” becomes twice?

This experiment deliberately reuses a key. XOR the two ciphertexts, and their shared key cancels out. A known message can then expose the other.

CONTEXT / NOT JUST CALCULATIONS

The field notes.

Simple arithmetic. Demanding rules.

01

What makes it a one-time pad?

A true OTP uses a uniformly random, independent secret key as long as the encoded message. Each key position encrypts only one message position. Given a fixed length, the ciphertext alone cannot distinguish between possible plaintexts.

02

The difficult part is the key.

Both correspondents need the same pad in advance, delivered secretly. Sending the key alongside the ciphertext defeats the protection. An OTP also does not authenticate the sender or detect tampering by itself.

03

The Soviet connection.

Soviet systems combined numerical codebooks with random pad numbers. Some pad material was duplicated, helping the American VENONA project recover parts of intercepted communications. VENONA names the codebreaking project, not the Soviet cipher.

What this reconstruction does—and where history ends

“Одноразовый блокнот” is a Russian descriptive term for a one-time pad, not a verified universal Soviet codename. Our character codebook and visual pad are teaching inventions. The decimal mode demonstrates addition modulo 10; particular historical systems had their own conventions.

The UTF-8 mode is modern. Generated pads use the browser’s cryptographically strong pseudorandom generator, not a demonstrated source of truly random key material. Therefore this workshop does not claim the perfect secrecy of a theoretical OTP. It blocks exact key reuse for encryption within this session, but does not detect partial overlaps or reuse in other sessions. Decrypting with the matching key is allowed.

A wrong key can produce plausible text. Successful decoding is not proof that the message is authentic. UTF-8 checks only whether the recovered bytes form valid text.
